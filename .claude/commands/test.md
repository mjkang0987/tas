이번 변경에서 테스트가 필요한 곳을 찾아 규약대로 추가한다.

## 1. 대상 찾기

```sh
cd client && pnpm test:required
```

이 게이트가 지목하는 파일이 곧 대상이다. 통과하더라도, 이번에 **동작을 바꾼 순수 함수**가 있으면 추가한다.

**대상 판정 기준** — `client/features/**` 의 `.ts` 중 **런타임 import 가 없는 것**(타입 임포트만 있거나 아예 없음). DB·React 환경 없이 바로 돌기 때문에 테스트를 안 쓸 이유가 없다.

**대상이 아닌 것** — React 컴포넌트, API 핸들러, Prisma 를 실제로 부르는 코드. 환경 구성이 선행돼야 한다. 이런 변경은 `/verify` 의 실제 구동으로 검증한다.

## 2. 무엇을 테스트하나

우선순위대로:

1. **실패 이력이 있는 동작** — `index.md` 의 횡단 규칙과 각주에 사고 기록이 있다. 그 회귀를 고정하는 테스트가 가장 값지다. 사고 원인을 그대로 재현하는 케이스를 반드시 넣는다(예: 금지된 UTC 읽기가 하루 밀리는 것).
2. **경계** — 빈 입력, 0·음수, 범위 끝(마감 시각, 월말, 윤년), 정규화·오버플로.
3. **분기 규칙** — 문서에 적힌 정책(용량 모델, 폴백 기본값, 스케줄 미설정 시 동작).
4. **함수 간 일관성** — 같은 판정을 두 함수가 공유하면 서로 어긋나지 않는지.

값이 낮은 것: 게터·단순 위임·타입만 바꾸는 래퍼. 커버리지 숫자를 위한 테스트는 쓰지 않는다.

## 3. 작성 규약

- 위치는 자유. **해당 모듈을 import 하기만 하면** 게이트가 인식한다(파일명 규칙 아님).
- `describe`·`it` 설명은 한국어로, **무엇이 보장되는지**를 적는다. "works correctly" 금지.
- 시간대에 의존하면 파일 최상단에서 `process.env.TZ` 를 먼저 지정한다(`Date` 생성 전이어야 한다). 운영은 KST 다.
- 테스트 픽스처는 헬퍼 함수로 만들어 케이스마다 달라지는 부분만 드러낸다.

## 4. 초록을 믿지 말 것 (필수)

새 테스트가 처음부터 통과하면 **소스를 일부러 망가뜨려 실패하는지 확인한다.**

```sh
# 예: 경계 비교를 뒤집고 테스트가 잡는지 본다
sed -i 's|<= close|< close|' features/booking/availability.ts
pnpm test          # 실패해야 정상
git checkout -- features/booking/availability.ts
pnpm test          # 다시 통과
```

실패하지 않는 테스트는 회귀를 못 잡는다. 보고에 **어떤 변이를 넣어 몇 건이 실패했는지** 적는다.

## 5. 마무리

```sh
cd client && pnpm test && pnpm test:required
```

복원까지 끝났는지 `git status` 로 확인한다. 변이 검사용 수정이 남으면 안 된다.
